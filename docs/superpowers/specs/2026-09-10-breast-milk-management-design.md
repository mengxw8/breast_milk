# “吨吨吨”母乳管理应用设计规格

日期：2026-09-10  
状态：已确认

## 1. 产品目标

“吨吨吨”是一款面向家庭使用的 Android 母乳库存管理应用。第一版完全离线运行，以“一袋一条记录、整存整取”为基本单位，解决三个核心问题：

1. 快速记录母乳入库并通过 Xprinter P203A 打印 40 x 30 mm 标签。
2. 通过扫描标签二维码或库存列表完成整袋出库和解冻管理。
3. 汇总当前库存、使用期限和临期风险，在首页及可选系统通知中提醒。

应用不提供医疗诊断。储存期限依据 CDC 的母乳准备与储存建议形成产品默认规则，界面应注明该规则是储存建议，家庭仍需结合实际卫生条件和专业医护意见判断。

参考资料：[CDC Breast Milk Preparation and Storage](https://www.cdc.gov/breastfeeding/breast-milk-preparation-and-storage/handling-breastmilk.html)

## 2. 第一版范围

### 包含

- 本机离线数据库
- 母乳入库、编辑、详情和状态历史
- 冷冻、冷藏、解冻、出库、过期和丢弃状态
- 常用食物标签和自由文本补充
- 纯数字唯一编号和二维码
- Xprinter P203A 蓝牙连接、测试打印、标签打印和重打
- 扫码出库与列表出库
- 当前库存及期限统计
- 首页临期提醒
- 用户可选的每日系统通知和提醒时间
- JSON 数据导出与合并恢复

### 不包含

- 账号、云同步或多设备实时同步
- 一袋母乳部分取用或剩余奶量
- 再次冷冻
- Web、iOS 或桌面端业务适配
- 医疗诊断、过敏结论或个性化储存期限建议

## 3. 品牌与视觉

### 名称和 Logo

- 产品名：吨吨吨
- Logo 构图：A1a，两滴等大的乳白奶滴位于两侧，一滴较小奶滴位于中间。
- 奶滴使用清晰的尖角、乳白层次和高光，身体圆润，表情可爱但克制。
- 不增加会形成多孩联想的配饰或额外小奶滴。
- 同一构图用于应用图标、启动页和品牌字标；小尺寸下允许移除面部细节，但必须保留“两大一小”的轮廓。

### 配色

采用 P2 配色：

- 珊瑚粉：品牌、入库主操作和主要强调
- 湖水蓝：扫码、连接和完成状态
- 琥珀色：临期提醒
- 浅粉白：页面背景
- 深暖灰：正文和数字
- 绿色只用于明确的成功或设备已连接状态

应用使用 Material 3 组件语义，保持沉浸式 edge-to-edge 系统栏。系统图标颜色必须随背景保持足够对比度。

## 4. 信息架构

底部固定五个入口：

1. 首页
2. 库存
3. 居中的扫码主按钮
4. 统计
5. 设置

扫码是最高优先级入口，入库按钮位于首页首屏。页面不使用营销式大标题或多层卡片，主要信息应适合单手操作和快速扫读。

### 首页

- 品牌和已绑定打印机状态
- 可用库存总袋数和总奶量
- 最早需要使用的日期
- 按风险排序的提醒区
- “母乳入库”和“扫码出库”快捷操作
- 按最早需要使用时间排序的优先清单

提醒顺序：

1. 解冻中且接近 24 小时期限
2. 已过期但尚未处理
3. 距冷冻最终过期不足一个月
4. 已超过冷冻最佳使用节点
5. 距冷冻最佳使用节点不足一个月
6. 冷藏母乳的剩余时间

### 库存

- 状态视图：在库、解冻中、已出库、已过期/已丢弃
- 按编号和食物搜索
- 按储存方式、食物、日期和状态筛选
- 默认按最早需要使用时间升序排列
- 每条记录显示奶量、储存方式、入库时间、编号和期限状态
- 详情页提供编辑、开始解冻、出库、丢弃、重打标签等符合当前状态的操作

### 统计

- 可用库存袋数和总 mL
- 解冻中袋数和总 mL
- 冷冻与冷藏袋数及奶量
- 一个月内进入最佳使用期
- 已过最佳使用期但未最终过期
- 一个月内最终过期
- 已过期但尚未处理
- 每袋详细期限清单和筛选

已出库和已丢弃必须分开统计，避免将过期损耗计入正常喂养量。

### 设置

- 蓝牙打印机搜索、绑定、连接状态和测试标签
- 常用食物管理
- 通知开关和每日提醒时间
- 数据导出与恢复
- 储存期限规则说明和来源

## 5. 入库流程

入库表单字段：

- 入库日期时间：默认当前时间，允许修改
- 奶量：必填、正整数、单位 mL，提供每次 10 mL 的加减按钮并允许直接输入
- 储存方式：默认“-21°C 冷冻”，可切换为“3°C 冷藏”
- 食物：常用和最近使用标签多选，并允许自由文本补充

保存前显示编号预览、期限预览和标签预览。正式编号仅在数据库事务中生成，防止预览或重复点击占用编号。

主操作为“保存并打印标签”，次操作为“仅保存，稍后打印”。执行顺序固定为：

1. 校验字段。
2. 在数据库事务中生成编号并保存记录。
3. 提交事务。
4. 请求打印。

打印失败不得回滚已保存记录。记录标记为“标签未打印”，首页和详情页提供重试。已打印记录被编辑后标记为“标签需更新”，重新打印沿用原编号。

## 6. 编号与二维码

编号为 16 位纯数字：

`yyyyMMddHHmmssSS`

- 前 14 位是用户选择的入库当地日期时间。
- 后 2 位是同一秒内从 `01` 开始的序号。
- 示例：`2026091011570101`。
- 数据库对编号建立唯一约束；发生冲突时在同一事务内递增序号并重试。
- 单秒达到 `99` 条时阻止继续生成并提示稍后重试。

二维码只编码编号，不嵌入奶量、食物或状态。这样记录被编辑后二维码仍然有效，扫码结果以本地数据库为准。

## 7. 标签设计

打印机为 Xprinter P203A，标签尺寸为横向 40 x 30 mm，采用已确认的 L1 布局：

- 左侧：尽可能大的正方形二维码，保留足够静区。
- 右侧：醒目的月日、时间和奶量。
- 次要信息：储存方式、食物摘要、完整编号。
- 食物优先显示标准标签，空间不足时最多显示前两项并截断；完整内容在 App 中查看。
- 标签为纯黑白设计，不依赖灰度或品牌颜色表达状态。

Android 端通过原生桥接调用项目现有的 Xprinter SDK AAR。实现阶段必须在 P203A 真机上确认当前指令模式、标签间隙、打印方向、浓度、中文字体和二维码扫描率，再固化 TSPL 或兼容指令参数。

## 8. 出库与解冻流程

### 扫码

扫码和从库存列表点击操作均进入同一个记录确认页：

- 在库冷冻：提供“开始解冻”和“直接出库”。
- 在库冷藏：提供“确认出库”。
- 解冻中：显示剩余时间并提供“确认出库”。
- 已出库：显示出库时间，禁止重复出库。
- 已丢弃：显示处理时间，禁止出库。
- 未知编号或非本应用二维码：提示未找到记录，不创建数据。

出库为整袋操作，记录出库时间并保留历史。成功后提供一次短时撤销入口；撤销通过新的状态事件实现，不删除原事件。

### 解冻

- 点击“开始解冻”立即记录时间，并从该时间开始 24 小时倒计时。
- 该规则比从“完全解冻”时起算更保守，界面必须明确说明。
- 一旦开始解冻，不允许返回冷冻状态或再次冷冻。
- 解冻中的记录在首页最高优先级区域展示。

## 9. 期限规则

### -21°C 冷冻

- 最佳使用节点：入库时间加 6 个自然月。
- 最终过期节点：入库时间加 12 个自然月。
- 距最佳使用节点一个月时开始首页提醒。
- 超过最佳使用节点后持续标记“建议尽快使用”。
- 距最终过期一个月时提升为紧急提醒。
- 超过最终过期节点后标记“已过期”。

### 3°C 冷藏

- 最终过期节点：入库时间加 4 x 24 小时。
- 因总期限不足一个月，所有冷藏在库记录都进入首页期限提醒，并显示小时或天数倒计时。

### 解冻中

- 最终过期节点：开始解冻时间加 24 小时。
- 开始解冻只能发生在尚未最终过期的冷冻记录上。

系统根据时间动态计算展示状态，同时保存计算所需的原始时间和规则版本。规则未来发生变化时，不应静默改变已有记录的期限；数据模型必须记录创建该记录时使用的期限规则版本。

## 10. 库存状态模型

核心状态：

- `frozenInStock`
- `refrigeratedInStock`
- `thawing`
- `checkedOut`
- `expired`
- `discarded`

主要转换：

- 冷冻在库 -> 解冻中 -> 已出库
- 冷冻在库 -> 已出库
- 冷藏在库 -> 已出库
- 任一在库状态超过最终期限 -> 已过期 -> 已丢弃
- 解冻中超过 24 小时 -> 已过期 -> 已丢弃

“已过最佳使用节点”是风险标记，不是独立库存状态。已过期记录仍代表实体库存，直到用户标记丢弃；但不计入可用库存。

## 11. 本地数据设计

建议使用 SQLite，并以仓储接口隔离 UI 与持久化实现。主要实体：

### 母乳记录

- 编号
- 入库时间和当地时区偏移
- 奶量 mL
- 储存方式
- 食物标签关联
- 食物自由文本
- 当前状态
- 最佳使用时间
- 最终过期时间
- 解冻、出库和丢弃时间
- 打印状态和最后打印时间
- 期限规则版本
- 创建时间和更新时间

### 状态事件

- 事件 ID
- 母乳编号
- 事件类型
- 事件时间
- 变更前后状态
- 必要的附加数据

### 食物标签

- 标签 ID
- 规范名称
- 使用次数
- 最近使用时间

### 设置

- 已绑定打印机名称和地址
- 通知开关和每日提醒时间
- 数据结构版本

数据库写入、编号生成和状态转换必须使用事务。业务层统一执行状态校验，界面不能直接更新状态字段。

## 12. 蓝牙、相机和通知

### 蓝牙

- 设置页搜索并绑定 P203A，保存其稳定设备标识。
- 后续打印自动尝试重连。
- 显示未连接、连接中、已连接、打印中、缺纸和错误等状态。
- Android 版本对应的蓝牙扫描与连接权限按需申请。

### 相机

- 仅在用户进入扫码功能时申请相机权限。
- 拒绝后说明用途，并提供进入系统设置的入口。

### 通知

- 默认关闭，由用户主动开启并选择每日提醒时间。
- 没有风险库存时不发送通知。
- 通知只显示临期袋数和总奶量，不显示食物等敏感详情。
- 库存变化、提醒时间变化和设备重启后重新计算任务。

## 13. 备份与恢复

- 导出为带数据结构版本的单个 JSON 文件。
- 导出内容包括记录、状态事件、食物标签和非设备敏感设置。
- 打印机地址和临时权限状态不进入备份。
- 导入前校验文件结构和版本，并自动导出当前数据作为安全备份。
- 恢复采用合并导入：编号不同的记录追加；编号相同的记录以 `updatedAt` 较新的版本为准；不自动删除本机已有记录。
- 状态事件按事件 ID 去重合并。
- 整个导入在单个事务中完成；任何校验或写入失败都回滚。
- 界面明确提示 JSON 可能包含个人健康相关信息，由用户自行选择安全位置保存。

## 14. 异常处理

- 数据保存失败：不生成有效记录、不打印，并保留用户输入以便重试。
- 保存成功、打印失败：记录保留并进入待打印状态。
- 蓝牙断开或缺纸：显示可操作的原因和重试入口。
- 重复扫码：只展示当前记录状态，不重复执行操作。
- 连续点击保存或出库：操作按钮进入忙碌状态，业务层仍以事务和唯一约束防重。
- 系统时间回拨：编号唯一约束和同秒序号保证不覆盖既有记录。
- 数据导入失败：回滚整个导入，不留下部分数据。
- App 意外关闭：已提交的数据不回滚，未完成打印可恢复重试。

## 15. 测试与验收

### 自动化测试

- 编号格式、同秒递增、冲突和 99 条上限
- 冷冻 6/12 自然月、冷藏 96 小时和解冻 24 小时期限
- 月末、闰年、时区偏移和系统时间变化
- 所有允许与禁止的状态转换
- 可用库存、实体库存、已出库和已丢弃统计口径
- 备份合并、较新记录覆盖、事务回滚和版本校验
- 入库校验、筛选、提醒和扫码结果的 Widget 测试
- Flutter 与 Android 打印桥接的契约测试

### 真机验收

- Android 13 设备上的相机、蓝牙和通知权限流程
- P203A 搜索、绑定、自动重连、测试打印和失败重试
- 40 x 30 mm 标签边距、方向、中文可读性和二维码扫描率
- 连续入库、快速重复点击和断开蓝牙后的数据一致性
- 冷冻、冷藏、解冻、出库、过期和丢弃全流程
- JSON 导出、合并恢复和失败回滚
- 沉浸式系统栏下的文字、按钮和底部导航不被遮挡

### 第一版完成标准

用户可以完全离线完成“入库并打印 -> 扫码开始解冻或出库 -> 查看库存与临期统计 -> 收到可选提醒 -> 导出并恢复数据”的闭环，任何打印或权限失败都不会造成库存记录丢失或重复出库。
