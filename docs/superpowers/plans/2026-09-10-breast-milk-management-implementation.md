# “吨吨吨”母乳管理应用实施计划

日期：2026-09-10  
依据：[母乳管理应用设计规格](../specs/2026-09-10-breast-milk-management-design.md)

## 实施原则

- Android 13 真机和 Xprinter P203A 是第一版验收目标。
- 所有业务数据本机离线保存，核心流程不得依赖网络。
- 先验证打印机 SDK 这一最高风险集成，再铺开完整业务界面。
- 数据先保存、后打印；打印失败不得破坏库存数据。
- 每个阶段先测试，再使用 AngularJS/Conventional Commits 格式提交中文说明。
- 每次提交只包含一个可解释、可验证的改动主题。

## 建议技术栈

- 状态管理：`flutter_riverpod`
- 路由：`go_router`
- 本地数据库：`drift` + SQLite
- 数据库生成：`drift_dev` + `build_runner`
- 日期格式：`intl`
- 扫码：`mobile_scanner`
- 通知：`flutter_local_notifications` + `timezone` + 本机时区适配包
- 文件导入导出：`file_picker`/`file_selector` 与系统分享能力
- 权限：相机由扫码插件触发；蓝牙权限优先由原生打印桥统一管理
- 打印：项目内 `printer-lib-3.5.8.aar`，通过 Kotlin `MethodChannel` 和 `EventChannel` 桥接

依赖版本在实施时通过 `flutter pub add` 选择与 Flutter 3.47.2、Dart 3.13.2 兼容的当前稳定版本，不在计划文档中硬编码过时版本。

## 阶段 2：P203A 打印链路风险验证

### Android 原生集成

- 将 `docs/printer-lib-3.5.8.aar` 复制到 `android/app/libs/`，由 Gradle 本地依赖加载。
- 在 Manifest 中增加与 Android 版本匹配的经典蓝牙权限：
  - Android 12 及以上：`BLUETOOTH_SCAN`、`BLUETOOTH_CONNECT`
  - 旧版本兼容：带版本限制的传统蓝牙和定位权限
- 在 Kotlin 打印管理器中调用 `POSConnect.init(applicationContext)`。
- 定义 `PrinterChannel`：
  - `getBondedDevices`
  - `startScan`
  - `stopScan`
  - `connect`
  - `disconnect`
  - `getStatus`
  - `printTestLabel`
  - `printMilkLabel`
- 用 EventChannel 推送扫描结果、连接状态和打印状态。
- 所有 SDK 回调只转换为稳定的应用错误码，不直接把厂商字符串暴露给 Flutter UI。

### Flutter 适配

- 定义 `PrinterGateway` 接口和 MethodChannel 实现。
- 建立仅供风险验证的打印机调试页：权限、已配对设备、扫描、连接和测试标签。
- 测试标签先打印边框、中文、16 位编号和二维码，不接业务数据库。

### 真机验收

- Android 13 能发现或读取已配对的 P203A。
- 连接、断开、重新连接不会崩溃。
- 40 x 30 mm 标签方向和间隙正确。
- 中文、编号和二维码均清晰，二维码可由当前手机稳定扫描。
- 确认 P203A 当前模式使用 TSPL 或兼容指令，并把最终参数集中到单一标签模板类。

## 阶段 3：领域模型、期限与编号

### 核心类型

- `MilkStorageMode`：冷冻、冷藏
- `MilkStatus`：冷冻在库、冷藏在库、解冻中、已出库、已过期、已丢弃
- `PrintStatus`：未打印、打印中、已打印、打印失败、标签需更新
- `MilkRecord`
- `MilkStatusEvent`
- `FoodTag`
- `ExpiryPolicy`

### 纯业务服务

- `MilkIdGenerator`
  - 生成 `yyyyMMddHHmmssSS`
  - 同秒序号 `01..99`
  - 接受编号占用查询接口，便于独立测试
- `ExpiryCalculator`
  - 冷冻加 6/12 个自然月
  - 冷藏加 96 小时
  - 解冻加 24 小时
  - 输出最佳使用、最终过期和提醒级别
- `MilkStateMachine`
  - 集中校验所有允许和禁止的状态转换
- `InventoryCalculator`
  - 可用库存、实体库存、解冻中、过期和丢弃口径

### 测试

- 编号格式、同秒递增、冲突、系统时间回拨和 99 条上限。
- 月末、闰年和时区下的 6/12 自然月计算。
- 冷藏 96 小时、解冻 24 小时。
- 所有状态转换矩阵。
- 已过期不计入可用库存但仍计入待处理实体库存。

## 阶段 4：SQLite 数据库与仓储

### 数据表

- `milk_records`
- `milk_status_events`
- `food_tags`
- `milk_food_tags`
- `app_settings`

### 关键约束

- `milk_records.id` 唯一。
- 奶量必须大于 0。
- 状态变化、事件追加和时间字段更新在同一事务内完成。
- 编号生成和记录插入在同一事务内完成。
- 每条记录保存 `expiry_rule_version`、`created_at`、`updated_at`。

### 仓储能力

- 创建和编辑记录
- 按编号查找
- 按状态、食物、储存方式和日期筛选
- 按最早需要使用时间查询
- 状态转换与短时撤销
- 打印状态更新与待打印查询
- 首页汇总与统计聚合

### 测试

- 使用内存 SQLite 做仓储集成测试。
- 验证事务回滚、唯一编号、筛选排序和统计 SQL。
- 验证编辑已打印记录会进入“标签需更新”。

## 阶段 6：入库与标签打印闭环

### 页面

- 日期时间选择，默认当前时间。
- 奶量整数输入和正负 10 mL 步进。
- 冷冻/冷藏分段选择，默认冷冻。
- 常用、最近使用食物标签和自由文本。
- 编号、期限和 L1 标签预览。
- “保存并打印标签”和“仅保存，稍后打印”。

### 流程

- 表单提交防重复。
- 数据库存储成功后调用 `PrinterGateway`。
- 打印结果更新 `PrintStatus`。
- 失败页面保留记录，并提供重新连接、重试和稍后打印。
- 标签模板固定为左侧大二维码，右侧日期、时间、奶量、储存方式、食物摘要和编号。

### 测试

- 表单必填、边界奶量和过去/未来时间处理。
- 同秒连续保存生成不同编号。
- 模拟打印失败时记录仍存在。
- 编辑打印过的记录触发“标签需更新”。
- P203A 连续打印多张标签不串号。

## 阶段 10：本地通知

### 功能

- 设置页默认关闭通知。
- 用户开启时请求 Android 通知权限并选择每日时间。
- 按时区安排下一次每日检查。
- 仅在有风险记录时发送袋数和总 mL，不展示食物详情。
- 库存变化、提醒时间变化和设备重启后重新安排。
- 点击通知打开对应风险清单。

### 测试

- 无风险不通知。
- 各风险等级聚合内容。

## 阶段 11：JSON 备份与合并恢复

### 导出

- 定义带 `schemaVersion`、导出时间和数据集合的 JSON 格式。
- 包含记录、事件、食物标签和非设备敏感设置。
- 不导出打印机 MAC、权限或运行时状态。
- 通过系统文件选择器保存，并提示文件包含个人信息。

### 导入

- 先解析并完整校验，不边读边写。
- 导入前自动生成当前数据备份。
- 编号或事件 ID 相同按较新 `updatedAt` 合并，不同记录追加。
- 不删除本机独有数据。
- 在单个数据库事务中完成，失败全部回滚。
- 导入完成后重新计算通知。

### 测试

- 往返导出导入。
- 重复导入幂等。
- 新旧记录合并。
- 损坏 JSON、未知版本和事务回滚。
